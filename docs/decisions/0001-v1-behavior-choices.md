# 0001: v1 behavior choices

Status: accepted (2026-11-01, amended 2026-11-02). Edge cases where more than one behavior was
reasonable, the one `zf` picks, and why. Each decision is pinned by the named test.

| # | Decision | Why | Test |
|---|---|---|---|
| 1 | An absolute path, `~`, anything through `..`, `.` and `./` are locations, not queries: an existing directory is searched, an existing file evaluated, and `DIR/word` with only `DIR` existing searches `DIR` for `word`. Relative paths (`src/main`, `./src`) stay path queries. A trailing `/.` means the same as a trailing `/` (`src/.` names the directory `src`). | Users type where they want to look; rejecting `../x` or `~/Downloads/cv` made them reach for `-p`, a flag for something the argument already said. Relative paths stay queries because `src/main` is far more often a fragment than a place. | `locations_are_absolute_home_parent_or_here`, `location_splits_into_root_and_term`, `parent_and_tilde_locations`, `trailing_dot_component_is_directory_name` |
| 2 | Case-insensitivity is Unicode lowercasing, not full case folding (`ß` does not match `ss`). Non-UTF-8 names fold ASCII bytes only. | Lowercasing is locale-independent and keeps one character per character; full folding changes lengths and needs tables for little gain in file names. Decoding invalid names lossily could invent matches. | `unicode_case_insensitive`, `non_utf8_names_match_ascii_bytes` |
| 3 | Git ignore rules (`.gitignore`, `.git/info/exclude`, global excludes) apply only inside a repository: a `.git` or `.jj` directory at or above the entry. `.ignore` applies everywhere. Ignore files in parent directories of the root apply under the same rule. A dotfiles `~/.gitignore` of `*` therefore hides nothing outside a repository. | Git rules mean what git means by them, and git only reads them inside a repository. jj reads `.gitignore` the same way, so its repositories count too. `.ignore` exists for tools like `zf` and has no repository condition. | `ignore_rules_from_parent_directories_apply`, `gitignore_outside_a_git_repository_is_not_applied`, `gitignore_applies_inside_a_jj_repository`, `dot_ignore_applies_outside_a_git_repository` |
| 4 | Generated directories are recognized by convention: `node_modules`, `__pycache__` and VCS directories always; `target`, `build`, `dist`, `out`, `coverage`, `vendor` only beside a project manifest; a virtual environment by its `pyvenv.cfg`. Files with these names are kept. | Skipping `build` by name alone hides hand-made folders such as `~/Documents/build`; a marker file is cheap to check and only checked for these names. | `build_directories_need_a_marker`, `target_needs_a_cargo_or_maven_project`, `virtual_environments_are_recognized_by_pyvenv_cfg`, `listed_names_that_are_files_are_kept` |
| 5 | A query that names a hidden or generated entry reaches it. A word spelling the whole name prints it without entering it; a path word enters each component it passes through, whose last component keeps prefix semantics (`./.env` also reaches `.envrc`). Fragments and a bare `*` name nothing. | Typing `.env` or `node_modules` is an explicit request; making it need `--all` would answer it with nothing. Printing without entering keeps `zf node_modules` from listing every nested package. | `a_term_spelling_the_whole_name_names_it`, `path_query_reaches_the_components_it_names`, `naming_a_skipped_directory_finds_it_without_entering_it` |
| 6 | A symlink is an entry: emitted when it matches, never descended. For `--files`/`--dirs`, `dir/` queries and built-in exclusions it takes its target's kind, so a `build` link to a directory is excluded. The target is stat'ed only when one of those needs it. | Never descending keeps the search inside its root and free of loops; using the target's kind keeps a link to a directory from slipping past rules written for directories. | `symlinked_directory_does_not_escape_root`, `symlink_to_directory_is_excluded_like_one` |
| 7 | `--files` with `--dirs` is a usage error. | Together they would print nothing, which silently answers a mistake. | `unknown_option_is_usage_error` |
| 8 | `--home` searches the whole home directory under the normal filtering. Roots from locations, `-p` and `--home` combine; repeated or nested roots are searched once. | Files live outside Documents, Desktop and Downloads (`~/src`, `~/Pictures`), and the normal filtering already skips caches and dotfiles, so the whole home costs about 35 ms. Combining roots follows from treating every place given as a place to look; deduplication keeps each entry printed once. | `home_searches_the_whole_home_directory`, `dedupe_drops_repeats_and_nested_roots`, `overlapping_roots_report_each_entry_once` |
| 9 | Recoverable traversal errors print one `zf: <path>: <operation>: <reason>` line each as they happen; no trailing count. | A line as it happens is visible during a long walk and stays next to the output it explains; a summary would arrive only at the end and repeat what was printed. | `unreadable_directory_continues_and_exits_3` |
| 10 | An output failure other than a broken pipe (e.g. disk full) prints a diagnostic and exits 2. | A partial result file must not look like a complete one; status 3 is for unreadable input, not lost output. | — |
| 11 | A malformed ignore rule (bad glob), in the tree or in a parent of the root, prints `zf: warning: ...` and does not change the exit status: the walk completed. | Status 3 promises that some entries were not searched; a bad rule loses no entries, so it only warns. | `malformed_ignore_file_warns_without_partial_status` |
| 12 | When stdout is a terminal, control characters and invalid UTF-8 print as `\xNN`; pipes, files and `-0` get raw bytes. | A file name must not be able to drive the terminal, but programs reading `zf` need the exact bytes to open the file. | `terminal_output_escapes_control_characters`, `piped_output_stays_raw` |
| 13 | A local result whose name starts with `-` keeps its `./`, so it never reads as an option downstream. | `zf rf \| xargs rm` must not hand `rm` the option `-rf`. | `local_name_starting_with_dash_keeps_dot_slash` |
| 14 | A second Ctrl+C exits 130 at once, for a walk stuck in slow I/O. | A worker blocked in `readdir` on a dead network mount never sees the stop flag; the user still needs a way out. | `second_ctrl_c_asks_for_an_immediate_exit` |
| 15 | A closed stderr drops diagnostics; the search finishes with its normal status. | `2>&1 \| head -1` is ordinary shell use; it must not crash a worker or change the result. | `closed_stderr_does_not_crash` |
| 16 | Every query word must match (AND); no words list everything visible. | Several words read like a search box, and one argument per query forced quoting for `annual report`. Listing everything with no words makes `zf --dirs` and `zf ~/Downloads` useful. | `every_term_must_match`, `no_query_lists_everything_visible` |
| 17 | A word starting with `.` matches names ending with it or equal to it, so `.env` finds dotfiles and `.tar.gz` is an exact compound extension. | One rule covers extensions, compound extensions and dotfiles; reading `.env` as extension-only found `prod.env` but not the `.env` the user meant. | `dot_name_matches_extension_and_the_hidden_name`, `compound_extension_is_exact` |
| 18 | A name word containing a dot must start at a word boundary (`main.rs` misses `domain.rs`). Plain words stay substrings. | A dotted word is almost always a file name; a substring match on it returned unrelated files ending in the same letters. | `dotted_name_starts_at_a_word_boundary` |
| 19 | `*` and `?` make a whole-name glob; brackets are literal. | `report-2?.pdf` and `*.rs` are how shells taught users to write patterns; the name, extension and path modes cannot say "starts with x, ends with y". Brackets stay literal because they are common in real file names. | `glob_matches_the_whole_name`, `glob_components_in_path_queries` |
| 20 | Names and words are lowercased and NFC-normalized, so decomposed names match composed text. | macOS and some archives store `café` decomposed; without normalization the same visible text would not match. | `decomposed_unicode_matches_composed_query` |
| 21 | A word starting with `-` that is not a known short-flag cluster is a query; `-p` needs its value as a separate argument. | `zf -draft` should find drafts, not fail on an unknown option; a separate `-p` value keeps `-pending` a query. | `query_starting_with_dash_needs_no_separator`, `dash_words_move_behind_the_separator` |
